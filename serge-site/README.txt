СЭРГЭ — сайт на php/html/js/css

Как запустить в Open Server Panel:
1. Положить папку serge-site в OpenServer\domains\  (получится OpenServer\domains\serge-site)
2. Запустить Open Server, в меню "Перезапустить"
3. Открыть в браузере http://serge-site/
   (PHP версия 7.4 или выше, БД не нужна)

Страницы: index.php, catalog.php, house.php?id=..., calculator.php
Расценки и дома лежат в data/rates.json и data/houses.json - там можно менять цифры.
Расчёт считает api/calc.php (функции в includes/functions.php).
Телефон, адрес и цифры на главной - демо, заменить на настоящие.

---- Что добавлено по макету и ТЗ ----
Меню как в макете: Дома, Строительство, Проекты, О компании, Журнал. Разделы stroitelstvo.php, company.php, zhurnal.php и statya.php заполнены примерным содержимым: данные лежат в data/stages.json, data/company.json, data/journal.json (демо-данные, заменить на настоящие; при переходе на БД - таблицы stages, company_info, team, journal_posts).
Каталог: фильтры по этажности, спальням, материалу, фундаменту, цене, гаражу и террасе + сортировка.
404.php, robots.txt и sitemap.xml (через .htaccess -> robots.php и sitemap.php), canonical, Schema.org хлебные крошки.
Для 404 и sitemap в Open Server должен работать mod_rewrite (по умолчанию включён).

---- План: база данных (потом) ----
Сейчас все данные берутся из data/*.json через includes/repository.php.
Места под базу помечены TODO(DB): grep -rn "TODO(DB)" .
Что есть: includes/config.php (USE_DB = false, доступы), includes/db.php (PDO, закомментирован),
database/schema.sql (заготовка таблиц для phpMyAdmin, не используется).
Когда будем делать БД: создать базу, импортировать schema.sql, перенести данные из JSON,
написать SQL в функциях repository.php, поставить USE_DB = true.

---- Сборка ----
Минимизация CSS/JS: tools/minify.sh (нужны Node.js и esbuild). Рядом с исходниками появляются *.min.css и *.min.js,
сайт подключает их сам (ASSET_MIN в includes/config.php). После правки CSS или JS запустите скрипт заново.

---- Документация ----
В папке docs (в корне репозитория): отчёт о разработке, описание программы, руководство пользователя, программа и методика испытаний.

ПУБЛИКАЦИЯ НА GITHUB PAGES (статическая версия)
GitHub Pages не выполняет PHP, поэтому сайт выгружается в HTML:
  SERGE_SITE_URL=https://<логин>.github.io/<репозиторий> php serge-site/tools/build-static.php ../dist
Скрипт tools/build-static.php прогоняет страницы через PHP, меняет ссылки *.php на *.html (house.php?id=X -> house-X.html),
создаёт sitemap.xml и robots.txt. Калькулятор в этой версии считает в браузере (calc.js, атрибут data-rates)
по тем же формулам, что api/calc.php. Автоматически это делает .github/workflows/pages.yml (ветка gh-pages).
Основная (PHP) версия для Open Server и будущей БД не меняется.


СЕРВЕРНАЯ ЧАСТЬ: MySQL, ЛИЧНЫЕ КАБИНЕТЫ, ЗАЯВКИ, АДМИН-ПАНЕЛЬ
Как развернуть (Open Server + phpMyAdmin):
  1. phpMyAdmin -> создать базу serge (кодировка utf8mb4_unicode_ci) -> Импорт: database/schema.sql, затем database/seed.sql
     (seed.sql - начальные данные из data/*.json; пересобрать: php tools/make-seed.php > database/seed.sql).
  2. Скопировать includes/config.local.php.example в includes/config.local.php, вписать доступы к базе, USE_DB = true и SETUP_KEY.
  3. Открыть /install.php, ввести SETUP_KEY и создать первого администратора (страница работает один раз). SETUP_KEY потом можно стереть.
  4. Войти на /login.php - откроется /admin/. Без config.local.php сайт работает как раньше, на data/*.json, без кабинетов.
  Если база не отвечает, публичные страницы показывают данные из data/*.json (сайт не падает); админка и кабинеты в этот момент недоступны.

Что умеет:
  - Заявка без аккаунта (/zayavka.php): имя, телефон, согласие на ПДн; из калькулятора и со страницы дома параметры расчёта
    прикладываются к заявке (сумма пересчитывается на сервере). Заявки видны в админке (Заявки).
  - Аккаунт клиента. Два пути: (а) клиент регистрируется сам (/register.php); (б) после согласия на сделку администратор в
    заявке нажимает «Создать кабинет»: логин - телефон, пароль генерируется, показывается ОДИН раз вместе с готовым текстом
    сообщения. Менеджер передаёт его клиенту сам (звонок, мессенджер, почта); при первом входе пароль нужно сменить.
    Автоматическая отправка паролей на любые номера из заявок намеренно НЕ сделана: номер никто не подтверждал, это путь для спама
    и утечки доступа. TODO(SMS): includes/notify.php - заглушка под SMS-шлюз/SMTP; когда появится подтверждение телефона кодом,
    можно включить автоматическую выдачу пароля.
  - Личный кабинет (/cabinet.php): объекты строительства клиента (процент, текущий этап, цепочка этапов, новости с фото) и его заявки.
    Заявки привязываются к клиенту только администратором или если клиент отправил их, будучи вошедшим (по номеру телефона
    автоматически не привязываются - иначе можно зарегистрироваться на чужой номер и увидеть чужие данные).
  - Админ-панель (/admin/): заявки (статусы, заметки, создание кабинета), клиенты (сброс пароля, отключение), объекты стройки и
    их новости, проекты домов (с фото), расценки и коэффициенты калькулятора, этапы строительства, журнал, страница «О компании»
    и контакты (шапка/подвал), администраторы, журнал действий. Всё, что можно менять в админке, сразу меняется на сайте.

Безопасность: пароли - password_hash (bcrypt); все SQL-запросы подготовленные; все формы с CSRF-токеном; вывод экранируется;
  сессия: httponly, SameSite=Lax, смена id при входе; вход ограничен (5 неудачных попыток на логин за 15 минут и 20 с адреса);
  заявки ограничены (5 в час с адреса, 3 в сутки на номер) + скрытое поле-ловушка; загрузки - только JPG/PNG/WebP до 5 МБ
  со случайным именем, в assets/uploads/.htaccess запрещено исполнение скриптов (на Nginx это правило нужно сделать в конфиге).
  На рабочем сайте выключите display_errors и включите HTTPS. Политика ПДн (privacy.php) - шаблон, её должен проверить юрист.
Статическая версия для GitHub Pages кабинеты и заявки не содержит: они работают только с PHP и базой.

ПОЧТА (письма клиентам с вашего адреса, например Gmail)
  1. Google-аккаунт -> двухэтапная проверка (включить) -> myaccount.google.com/apppasswords -> создать «пароль приложения» (16 букв).
  2. В includes/config.local.php добавить MAIL_HOST smtp.gmail.com, MAIL_PORT 465, MAIL_SECURE 'ssl', MAIL_USER (ваш адрес), MAIL_PASS (пароль
     приложения); образец - includes/config.local.php.example. Основной пароль от почты НЕ вписывать.
  3. Админка -> «Почта» -> «Отправить тест»: письмо должно прийти (проверьте и «Спам»). Если не пришло, причина будет написана на странице.
  Что отправляется: клиенту, оставившему почту в заявке, - подтверждение (не чаще 3 писем в сутки на адрес); при выдаче/сбросе пароля -
  если отметить галочку «отправить письмом». Ошибки почты на приём заявок не влияют (пишутся в журнал ошибок PHP).
  Если в Open Server письма не уходят из-за сертификатов, в php.ini задайте openssl.cafile (путь к cacert.pem).
  SMS пока заглушка (includes/notify.php, TODO(SMS)).
